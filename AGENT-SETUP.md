# AGENT-SETUP V2 - настройка комплекта агентом

Ты - ИИ-агент, которому дали ссылку на этот репозиторий со словами `настройся`. Настрой Codex на личном ноутбуке безопасно, не перезаписывай существующие файлы и докажи результат проверками.

## 1. Зафиксируй план и границы

- Определи систему: Windows, macOS или Linux.
- Работай только на компьютере текущего пользователя.
- До изменений назови найденные инструменты, целевые папки, 2-5 шагов и критерии приемки.
- Собери все блокирующие вопросы одним сообщением. Не спрашивай то, что можно безопасно определить автоматически.
- Не удаляй данные, не меняй доступы, не публикуй, не отправляй сообщения и не выполняй `git push` без явного подтверждения.

## 2. Проверь среду

Проверь и покажи результат:

```text
Codex установлен и запускается
git --version
GitHub-аккаунт принадлежит пользователю
GitHub-аутентификация настроена или отмечена как остаток
двухфакторная аутентификация GitHub включена или отмечена как остаток
```

Если Git или аутентификация отсутствуют, не обходи защиту. Дай одну точную инструкцию пользователю и продолжи все независимые шаги.

## 3. Что устанавливается

В `skills/` лежит ядро из 21 скилла и навигатор `_INDEX.md`. Полный список указан в `README.md`. Количество скиллов не расширяй автоматически.

Целевые папки:

- Codex на macOS и Linux - `~/.codex/skills/`;
- Codex на Windows - `%USERPROFILE%\.codex\skills\`;
- Claude Code, только если он реально установлен, - соответствующая папка `~/.claude/skills/` или `%USERPROFILE%\.claude\skills\`.

## 4. Получи комплект

Источник:

```text
https://github.com/Yzyvan/vibe-skills
```

Клонируй его в отдельную локальную папку пользователя. Не используй существующий рабочий проект как временную папку. Если репозиторий уже клонирован, сначала выполни `git status` и не обновляй его при наличии несохраненных изменений.

Пример для macOS и Linux:

```bash
git clone https://github.com/Yzyvan/vibe-skills.git
```

Пример для Windows PowerShell:

```powershell
git clone https://github.com/Yzyvan/vibe-skills.git
```

## 5. Установи без перезаписи

1. Создай целевую папку скиллов, если ее нет.
2. Сравни имена существующих папок со скиллами из комплекта.
3. Совпадающие папки не перезаписывай. Сравни версии и покажи конфликт пользователю.
4. Скопируй только отсутствующие папки и `_INDEX.md`.
5. Не удаляй лишние пользовательские скиллы.

Операция должна быть повторяемой: второй запуск пропускает совпадающие файлы и не создает дубли.

## 6. Подключи архитектуру V2

Прочитай `AGENTS.template.md`. Найди действующий файл правил:

- Codex - глобальный или проектный `AGENTS.md`;
- Claude Code - глобальный или проектный `CLAUDE.md`.

Если файла нет, предложи создать его из шаблона. Если файл существует, не перезаписывай его. Покажи предлагаемые дополнения, убери смысловые дубли и получи подтверждение перед изменением.

После подключения должны работать: Шаг 0, PDCA, один управляемый заход, пакет блокирующих вопросов, лимит циклов, контрольные точки, HANDOFF V2, дедупликация уроков, три уровня инициативы и проверка результата.

## 7. Настрой сохранность данных

- Постоянные проекты держи в обычной локальной папке пользователя, не внутри временной директории.
- Для каждого рабочего проекта проверь `git status`, наличие `.gitignore` и удаленного приватного GitHub-репозитория.
- Если приватного репозитория нет, только предложи его создать. Создание, приглашение участников и первый `git push` требуют явного подтверждения.
- Секреты, токены, `.env`, сессии и исходные персональные данные добавь в исключения до первого коммита.
- Публичный `vibe-skills` не используй как хранилище клиентских или личных данных.
- Локальная копия и GitHub защищают от потери, но не заменяют резервную копию файлов, которые нельзя хранить в Git.

## 8. Проверь результат

1. В целевой папке ровно 21 установленная папка из комплекта со `SKILL.md`.
2. `_INDEX.md` установлен и читается.
3. Правила содержат V2-разделы из шага 6.
4. Пробная задача начинается строкой `Беру скиллы: ...` и показывает Plan.
5. Локальная папка проекта существует и сохраняется после перезапуска Codex.
6. Для GitHub назван точный статус: готов, требует входа, требует приватного репозитория или требует разрешенного `git push`.
7. Ни один существующий файл не был молча перезаписан.

## 9. Доложи пользователю

Назови:

- систему и путь установки;
- сколько скиллов установлено, пропущено и конфликтует;
- подключена ли архитектура V2;
- готовность Git и GitHub;
- что хранится локально и что подтверждено в удаленном приватном репозитории;
- какие внешние действия не выполнялись без явного подтверждения;
- доказанный результат, непроверенный остаток, риск и следующий шаг.

## Ограничения

- Не записывай секреты и личные данные в скиллы, навигатор или публичный Git.
- Не меняй настройки безопасности GitHub ради упрощения установки.
- Не выдавай сторонние скиллы за собственные - источники указаны в `THIRD_PARTY_NOTICES.md`.
- Не копируй закрытые офисные скиллы из чужих установок. Подключай их только из официального источника и по правилам лицензии.
